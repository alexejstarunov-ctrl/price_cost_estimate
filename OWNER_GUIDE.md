# Руководство владельца

Это инструкция для того, кто владеет репозиторием и отвечает за приложение
«Смета на укладку плитки». Она рассчитана на человека без опыта разработки:
каждый шаг — конкретная команда или клик.

- Приложение: https://alexejstarunov-ctrl.github.io/price_cost_estimate/
- Код и данные: https://github.com/alexejstarunov-ctrl/price_cost_estimate

Как приложение устроено внутри и что оно умеет — в [README.md](README.md).
Здесь — как его обслуживать.

---

## 1. Один раз: поставить инструменты на ПК

Нужны две программы. Обе бесплатные, ставятся «далее-далее».

1. **Git** — https://git-scm.com/downloads. На Windows при установке оставьте всё по умолчанию.
2. **Node.js** — https://nodejs.org, версия **22 LTS** (кнопка слева, не «Current»).

Проверка. Откройте терминал (Windows: «Пуск» → `cmd` или PowerShell; Mac: «Терминал») и введите:

```bash
git --version
node --version
```

Должны появиться версии, например `git version 2.4x` и `v22.x.x`. Если пишет «не является
командой» — закройте терминал, откройте заново (иногда нужен перезапуск после установки).

---

## 2. Скопировать репозиторий себе

```bash
cd Documents
git clone https://github.com/alexejstarunov-ctrl/price_cost_estimate.git
cd price_cost_estimate
npm install
```

`npm install` скачивает зависимости, займёт минуту. Делается один раз.

Запустить приложение локально, чтобы посмотреть изменения до публикации:

```bash
npm run dev
```

В терминале появится адрес вида `http://localhost:5173/price_cost_estimate/` — откройте его
в браузере. Остановить — `Ctrl+C` в терминале.

---

## 3. Где лежат расценки

Все цены — в двух текстовых файлах. Открываются любым редактором (Блокнот, VS Code).

| Файл | Что там |
|---|---|
| `src/data/works.ts` | 47 позиций работ и материалов с ценами **для Москвы** и рыночным разбросом |
| `src/data/regions.ts` | Города: во сколько раз дешевле Москвы и реальные цены города по ключевым позициям |
| `src/data/templates.ts` | Готовые наборы работ «Санузел», «Фартук», «Балкон», «Пол» |

Одна позиция выглядит так:

```ts
{ id: 'w-wall', name: 'Плитка на стену, прямая укладка', unit: 'м²',
  category: 'Укладка плитки', price: 1750, range: [700, 1750], source: 'base' },
```

Поменять цену — исправить число в `price`. Единственное строгое правило: **не трогать
`id`** (то, что в кавычках после `id:`). На него ссылаются шаблоны и сохранённые у людей сметы.

## 4. Обновить расценки с помощью LLM

В репозитории лежит готовая инструкция для нейросети:
`.claude/skills/update-prices/SKILL.md`. Она объясняет модели структуру файлов, где брать
цены, что нельзя ломать и как проверить результат. Работает с любой LLM.

### Вариант А — Claude Code (самый удобный, всё делает сама)

Один раз установить:

```bash
npm install -g @anthropic-ai/claude-code
```

Дальше каждый раз:

```bash
cd Documents/price_cost_estimate
claude
```

и написать в чате, например:

> Обнови расценки на укладку плитки на текущий месяц. Добавь город Воронеж.

Инструкция из `.claude/skills/update-prices` подхватится автоматически: модель найдёт
цены, поправит файлы, запустит проверку и сборку, предложит коммит. Вам останется
подтвердить и выполнить `git push` (шаг 5).

Нужна подписка Claude или API-ключ Anthropic — программа попросит войти при первом запуске.

### Вариант Б — любая другая LLM (ChatGPT, Gemini, DeepSeek, Cursor, GigaChat…)

1. Откройте файл `.claude/skills/update-prices/SKILL.md`, скопируйте весь текст
   и вставьте в чат первым сообщением — это инструкция для модели.
2. Приложите (или вставьте текстом) файлы `src/data/works.ts` и `src/data/regions.ts`.
3. Напишите задачу: «Обнови цены на сентябрь 2026 по Москве и Ростову, верни файлы целиком».
4. Модель вернёт файлы целиком — сохраните их поверх старых в те же места.
5. Проверьте, что ничего не сломано:

   ```bash
   npm run check:prices
   npm run build
   ```

   Если проверка пишет `ОШИБКА: ...` — покажите строку модели и попросите исправить.
   `Данные в порядке` — можно публиковать.

Совет: просите модель называть источники цен (ссылки). Так вы сможете проверить
сомнительное число сами и не опубликовать выдумку.

## 5. Опубликовать изменения

Публикация — это отправка изменений на GitHub. Дальше всё автоматически.

```bash
git add -A
git commit -m "chore: расценки на сентябрь 2026"
git push
```

При первом `git push` GitHub попросит войти — откроется браузер, войдите под своим
аккаунтом `alexejstarunov-ctrl`.

Через одну-две минуты сайт обновится. Проверить ход: вкладка **Actions** на странице
репозитория — зелёная галочка у последнего запуска значит «опубликовано».

**Красный крестик** — откройте запуск, там будет либо `ОШИБКА: ...` от проверки данных
(исправьте цену и повторите шаг 5), либо ошибка сборки (пришлите текст тому, кто помогает
с кодом).

У людей, которые уже установили приложение на телефон, новая версия подхватится сама при
следующем открытии с интернетом.

---

## 6. Кто имеет доступ

Всё управление — на странице репозитория, **Settings**.

- **Collaborators** — люди с правом писать в репозиторий (могут менять цены и код).
  Добавить: *Add people* → логин GitHub → роль *Write*. Убрать — *Remove* в той же таблице.
- **Deploy keys** — ключи для конкретных компьютеров или помощников, без доступа к
  вашему аккаунту. Один такой ключ (`claude-deploy`) сейчас добавлен для машины, с которой
  делали приложение. Не нужен — удалите, ничего не сломается.
- **Pages** — откуда публикуется сайт. Должно стоять *Source: GitHub Actions*. Не менять.

Никаких паролей, ключей и данных пользователей в репозитории нет: сметы хранятся только
в телефонах у тех, кто ими пользуется.

## 7. Частые задачи

**Добавить город.** В `src/data/regions.ts` добавьте блок по образцу существующих:

```ts
{ id: 'voronezh', label: 'Воронеж', factor: 0.65,
  prices: { 'w-wall': 1100, 'w-floor': 950 } },
```

`factor` — во сколько раз цены в среднем ниже московских, `prices` — реальные цены
города по тем позициям, которые удалось найти (id берите из `works.ts`). Проще всего —
поручить это LLM по шагу 4.

**Добавить позицию.** В `src/data/works.ts` в конец нужного раздела, с новым `id`
(`w-` для работ, `m-` для материалов) и единицей из списка: `м²`, `п.м`, `шт`, `компл`,
`меш`, `кг`, `л`, `точка`.

**Изменить готовые наборы работ** («Санузел 3 м²» и другие) — `src/data/templates.ts`.

**Изменить текст внизу PDF-сметы** — файл `src/components/PrintView.tsx`, фраза
«Смета носит предварительный характер…».

**Изменить цвета** — начало файла `src/styles.css`, блок `:root` (светлая тема) и
`prefers-color-scheme: dark` (тёмная).

После любого изменения: `npm run check:prices` → `npm run build` → шаг 5.

---

## 8. Чего не делать

- Не переименовывать и не удалять `id` позиций — сломаются шаблоны и сохранённые сметы.
- Не включать автоматический сбор цен с Профи.ру (`ENABLE_PROFI`) — их пользовательское
  соглашение это запрещает, а репозиторий публичный. Авито и Яндекс Услуги технически
  закрыты для сбора; подробности — в README, раздел «Откуда берутся цены».
- Не удалять `.github/workflows/` — без них сайт не публикуется.
- Не коммитить папку `node_modules` (она в `.gitignore`, но если увидите её в `git status` —
  что-то пошло не так, остановитесь).

## 9. Если что-то сломалось

```bash
git status                 # что изменено
git checkout -- src/data/works.ts   # вернуть один файл к последней опубликованной версии
git log --oneline          # история изменений
git revert HEAD            # отменить последний коммит (создаст новый, «отменяющий»)
git push
```

Самый надёжный откат: найти во вкладке **Actions** последний зелёный запуск, посмотреть
его коммит, и выполнить `git revert` для всего, что было после него.

Если приложение не открывается на телефоне у всех — проверьте **Settings → Pages**: там
должен быть адрес сайта и надпись «Your site is live».

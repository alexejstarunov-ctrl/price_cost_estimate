# Обновление расценок

Ты редактируешь данные приложения-сметчика для плиточников. Приложение живёт на
GitHub Pages и собирается автоматически после `git push`. Твоя задача — привести
цены к актуальному рынку, не сломав структуру данных.

## Где что лежит

| Файл | Что внутри |
|---|---|
| `src/data/works.ts` | База: 47 позиций работ и материалов с ценами **для Москвы** и рыночным диапазоном |
| `src/data/regions.ts` | Города: коэффициент к Москве плюс реальные цены города по ключевым позициям |
| `src/data/templates.ts` | Готовые наборы работ (санузел, фартук…) — ссылаются на id из works.ts |
| `README.md` | Таблица регионов и дата среза цен — обнови вместе с данными |

Другие файлы не трогай: интерфейс, расчёт материалов и сборка от цен не зависят.

## Контракт данных

Позиция в `works.ts`:

```ts
{ id: 'w-wall', name: 'Плитка на стену, прямая укладка', unit: 'м²',
  category: 'Укладка плитки', price: 1750, range: [700, 1750], source: 'base' }
```

- `id` — латиница, префикс `w-` для работ и `m-` для материалов. **Никогда не переименовывай
  и не удаляй существующие id**: на них ссылаются шаблоны и сохранённые сметы пользователей.
  Устаревшую позицию оставь, но поправь цену; новую добавляй с новым id.
- `price` — целые рубли за единицу, Москва и область, типичное значение (не минимум).
- `range` — наблюдаемый разброс по России `[минимум, максимум]`; московская цена обычно
  у верхней границы.
- `unit` — одно из: `м²`, `п.м`, `шт`, `компл`, `меш`, `кг`, `л`, `точка`.
- `category` — одно из значений массива `CATEGORIES` в том же файле.
- `source` — всегда `'base'`.

Регион в `regions.ts`:

```ts
{ id: 'rostov', label: 'Ростов-на-Дону', factor: 0.85,
  prices: { 'w-wall': 1500, 'w-floor': 1250, 'w-grout': 100 } }
```

- `factor` — во сколько раз цены города в среднем отличаются от Москвы; применяется только к
  позициям, которых нет в `prices`.
- `prices` — реальные цены города по конкретным id. Заполняй только тем, что нашёл в
  источниках; не вычисляй их из коэффициента — тогда пометка «прайсы города» в приложении
  станет ложью.
- Первый регион — `msk` с `factor: 1`, это база. Не меняй.

## Откуда брать цены

Годятся открытые источники, которые публикуют цены для привлечения клиентов:

- региональные страницы Профи.ру: `https://profi.ru/geo-<город>/remont/plitochniki/price/`
  (коды: `saratov`, `volgograd`, `rnd`, `smr`, `tambov`, `nnov`, `ksdr`, `spb`) — смотреть
  глазами в браузере можно, **автоматически парсить нельзя**, это запрещено их соглашением;
- прайс-листы местных ремонтных компаний и бригад (сайты вида «плиточные работы <город> цена»);
- сметные справочники и калькуляторы подрядчиков.

Не годятся: Авито и Яндекс Услуги (закрыты от автоматического сбора, а вручную —
нерепрезентативны), цены из чужих приложений, догадки. Если по позиции данных нет —
оставь текущее значение и скажи об этом.

Бери **типичную** цену за работу мастера или небольшой бригады, не строительной компании
«под ключ» (у них верх диапазона) и не демпинг «от 300 ₽» из объявлений.

## Порядок работы

1. Прочитай оба файла целиком, чтобы видеть текущие id и структуру.
2. Собери цены по источникам выше. Веди список: город → позиция → цена → ссылка.
3. Правь `works.ts`: цены и диапазоны. Новую позицию добавляй в конец нужного раздела.
4. Правь `regions.ts`: точечные цены и при необходимости коэффициент. Новый город —
   по образцу существующих, `label` по-русски, `id` латиницей.
5. Обнови в `README.md` дату среза («срез <месяц год>») и таблицу регионов.
6. Проверь данные и сборку:

   ```bash
   npm run check:prices   # ловит дубли id, нули, диапазоны наоборот, битые ссылки
   npm run build
   ```

   Пока `check:prices` выдаёт «ОШИБКА», дальше не иди — исправь.
7. Закоммить и отправь. В сообщении коммита перечисли источники:

   ```
   chore: расценки на <месяц год>

   Москва: Профи.ру /price/, прайс <компания>.
   Ростов: profi.ru/geo-rnd, <сайт>.
   Добавлен город <название>.
   ```

   После `git push` сайт обновится сам за одну-две минуты.

## Если ты работаешь в обычном чате, а не в агентном режиме

Тебе не дадут запускать команды. Тогда:

- попроси прислать оба файла целиком, если их нет в контексте;
- верни **каждый изменённый файл целиком**, а не фрагментами, в отдельном блоке кода
  с именем файла — пользователь сохранит их поверх старых;
- отдельным списком напиши, что именно изменилось и по каким источникам;
- напомни пользователю выполнить `npm run check:prices`, затем `npm run build`,
  затем `git add -A && git commit -m "..." && git push`.

## Чего не делать

- Не менять и не удалять `id`.
- Не выдумывать цены и не подгонять их под красивые числа.
- Не записывать в `prices` региона значения, вычисленные из коэффициента.
- Не трогать файлы вне `src/data/` и `README.md`.
- Не запускать `npm run scrape` с включённым Профи.ру ради «актуальных» цен.
